# خارطة الطريق

كل مرحلة تُمثل Issue مستقلًا على GitHub وفق [AGENTS.md](../AGENTS.md). الشروط أدناه معايير قبول مستقبلية؛ لا توجد اختبارات تطبيق الآن.

## المرحلة 0 — تأسيس المتطلبات

**المحتوى:** اعتماد وصف المنتج والنطاق والمنصات واللغة والإطار والتخزين والترخيص؛ إعداد المستودع وحماية الفرع الرئيسي وقوالب المساهمة؛ تثبيت CI المناسب.

**شرط النجاح:** جميع ADRs الأساسية معتمدة؛ مراجعة بشرية للوثائق؛ ينجح فحص تنسيق Markdown على Windows وmacOS وLinux. قبل بدء التنفيذ، ينجح CI في تحليل التطبيق واختباراته وبناء الهدف المضيف على الأنظمة الثلاثة، وبناء الويب وAndroid.

**خارجها:** أي شيفرة تطبيق أو ادعاء دعم منصة أو إصدار منشور.

## المرحلة 1 — هيكل التطبيق وإطار التشغيل

**المحتوى:** إنشاء المشروع بالإطار المعتمد، إعداد الترجمة العربية/الإنجليزية، هيكل الوحدات وCI الحقيقي، وصفحة أولية بسيطة.

**شرط النجاح:** تحليل ساكن نظيف واختبارات وحدة أولية؛ بناء Windows وmacOS وLinux على runners الموافقة، وبناء الويب وAndroid؛ اختبار آلي يثبت العربية الافتراضية والتبديل إلى الإنجليزية.

**خارجها:** تنزيلات فعلية، حسابات، مزامنة، وميزات خلفية.

## المرحلة 2 — إضافة رابط وتنزيل مباشر

**المحتوى:** إدخال رابط HTTP/HTTPS، التحقق من المدخل، بدء تنزيل، حفظ الملف، وعرض الحالة والتقدم.

**شرط النجاح:** اختبارات باستخدام خادم محلي وهمي لنجاح التنزيل، الاستجابة الفاشلة، انقطاع الشبكة، غياب طول المحتوى، رابط غير صالح، تحويل إلى عنوان محظور، واسم ملف خطر. بناء وفحوص جميع أهداف CI ينجح.

**خارجها:** متصفح مدمج، استخراج الروابط من الصفحات، تورنت، وتجاوز قيود الوصول.

## المرحلة 3 — إدارة قائمة التنزيلات

**المحتوى:** قائمة انتظار، إيقاف واستئناف وإلغاء ضمن ما تدعمه المنصة والخادم، وإعادة المحاولة برسالة واضحة.

**شرط النجاح:** اختبارات الانتقال بين الحالات، تنزيلين متزامنين، فشل الاستئناف عند عدم دعم الخادم، إعادة المحاولة، الإلغاء أثناء الكتابة، وعدم إفساد ملف مكتمل. قياس حدود التوازي واختبارها.

**خارجها:** وعد استئناف عام أو عمل خلفي موحد على كل الأنظمة.

## المرحلة 4 — حفظ محلي وإعدادات

**المحتوى:** قاعدة بيانات محلية للبيانات الوصفية، إعدادات المجلد، واستعادة قائمة المهام بعد إعادة التشغيل.

**شرط النجاح:** اختبارات ترحيل المخطط من إصدار سابق، قاعدة بيانات تالفة، صلاحيات كتابة مرفوضة، أسماء ملفات مكررة، وإغلاق غير متوقع. اختبارات خصوصية تؤكد عدم حفظ أسرار أو محتويات ملفات في قاعدة البيانات.

**خارجها:** حسابات المستخدمين، خادم سحابي، ومزامنة.

## المرحلة 5 — إكمال التغطية وإصدار أولي

**المحتوى:** مراجعة قابلية الوصول والترجمات، اختبار يدوي موثق على كل منصة، سياسة إصدار آلية من GitHub، ملاحظات إصدار ومراجعة تراخيص الاعتماديات.

**شرط النجاح:** كل اختبار آلي أخضر؛ قائمة اختبار يدوي موقعة بالتاريخ ونسخة النظام لكل منصة؛ لا أعطال حرجة مفتوحة؛ بناء الإصدار والملفات المنشورة صادرة من GitHub Actions فقط، مع تحقق سلامة الملفات.

**خارجها:** وعود أمنية أو توافق غير موثق أو ميزات غير مختبرة.
