# ADR-0002: إطار التطبيق

- الحالة: **مقبول**
- التاريخ: 2026-11-07
- اعتمده صاحب المشروع في المحادثة بتاريخ 2026-11-07.

## السياق

المنصات المطلوبة Windows وmacOS وLinux والويب وAndroid. تطبيق تنزيلات الملفات يعتمد على قدرات النظام، لذلك لا يكفي أن يرسم الإطار واجهة مشتركة؛ يجب اختبار التخزين والعمل بالخلفية واختيار الملفات على كل نظام.

## الخيارات

1. **Flutter / Dart**: قاعدة واجهة مشتركة؛ لديه أهداف بناء للمنصات المطلوبة، لكن إمكانات تنزيلات الخلفية وحفظ الملفات ستحتاج تكاملات خاصة بكل منصة.
2. **واجهات ويب مع Tauri للسطح المكتب وواجهة ويب مستقلة وAndroid منفصل**: مشاركة في الويب، مع أكثر من مسار تطبيق وصيانة مختلفة.
3. **تطبيقات أصلية منفصلة**: تكامل أعمق مع كل نظام مقابل تكرار واجهة ومنطق أكثر.

## القرار

اعتماد Flutter وDart كبداية، مع فصل منطق التنزيل عن موائمات المنصات.

## السبب

يقدم مسارًا واحدًا للواجهة واللغة والمنطق المشترك عبر المنصات المطلوبة، ويتيح بناء الويب وسطح المكتب وAndroid من قاعدة مشروع واحدة. لا يثبت ذلك تكافؤ قدرات التنزيل.

## الأثر والتحقق

تثبت نسخة SDK في ملفات المشروع. يجب أن يبني CI هدف النظام المضيف على Windows وmacOS وLinux، ويشغل التحليل والاختبارات على الأنظمة الثلاثة؛ كما يجب بناء الويب وAndroid في CI. اختبار Android يحتاج تثبيت Android SDK. أي هدف يتعذر بناؤه يوسم بوضوح ولا يُعلن مدعومًا. لم تُجرَ هذه التجارب بعد.
